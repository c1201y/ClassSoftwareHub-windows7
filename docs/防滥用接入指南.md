# 自建后端防滥用接入指南

> 面向 Windows 10 桌面端（ClassSoftwareHub-Desktop）开发者。
> 本文说明 `api.classsoftwarehub.cn` 对客户端的调用约束：哪些请求会被拦、凭什么放行、超限时返回什么、客户端应如何处理。
> 服务本身的端点契约见后端仓库 `csh-api` 的 `docs/后端使用文档.md`；本文只讲防滥用相关的判定与配额。
> 与本文配套的密钥、判定表与威胁模型见同目录 `正版校验与服务端接入.md`。

---

## 1. 适用范围

| 项 | 说明 |
|---|---|
| 后端地址 | `https://api.classsoftwarehub.cn` |
| 受约束的对象 | 桌面端发起的全部 `/api/**` 请求 |
| 不受约束的对象 | 纯本地功能（小工具、抽号、计时等）不触网，与本文无关 |
| 文档基准 | 2026-11-02（对应桌面端 `1.2.0-insider1.6`、后端 `main`） |

后端用四层手段控制滥用，四层相互独立：

| 层 | 目的 | 触发后的表现 |
|---|---|---|
| ① 授权闸门 | 阻止非官方构建免费占用服务端资源（提交、上传签名、喊话） | HTTP 403 + `code: csh_license_required` |
| ② 配额限流 | 限制单设备 / 单 IP / 全站的调用频率与总量 | HTTP 429 + 说明文案（部分带 `scope`） |
| ③ 内容校验 | 拒绝畸形或越界的载荷，避免脏数据进入审核流 | HTTP 400 + 逐条中文原因 |
| ④ 票据与签名 | 下载链路凭短时票据取流，防止直链被外传滥用 | HTTP 403 / 410，需回站重新取票 |

## 2. 授权闸门

### 2.1 请求头契约

桌面端在**每个**受保护请求上带下列头。名称大小写不敏感，值不做 URL 编码。

| 请求头 | 必填 | 内容 | 示例 |
|---|---|---|---|
| `X-CSH-Build` | 是 | 构建号，≤ 96 字符，**不得含竖线 `&#124;`** | `dv1.2.0-insider1.6+20261102T0730Z` |
| `X-CSH-Sig` | 官方包必填 | 构建签名，64 位十六进制（32 字节） | `9f3c…`（见 §2.3） |
| `X-CSH-Device` | 是 | 设备码，≤ 64 字符，须跨启动稳定 | `3b1f9c0d7a2e4f81` |
| `X-CSH-Lic` | 有则带 | 授权令牌，`base64url(payload).base64url(mac[0..16])` | `eyJ2Ijox…` |
| `X-CSH-Ver` | 建议 | 客户端版本号，仅用于服务端排障 | `1.2.0-insider1.6` |

响应侧需要客户端处理的头：

| 响应头 | 含义 | 客户端动作 |
|---|---|---|
| `X-CSH-Lic` | 服务端新签发的令牌 | 持久化覆盖旧值 |
| `X-CSH-Lic-Exp` | 令牌到期时间（Unix 秒，`0` 表示长期） | 与令牌一起存，用于界面展示 |

### 2.2 受保护的路由

| 路由 | 是否过闸门 |
|---|---|
| `/api/submit`、`/api/echocave`、`/api/feedback`、`/api/oss-sign`、`/api/announce/*` | **是** |
| `/api/license/activate` | 否（兑换本身不能要求授权，否则死循环） |
| `/api/dl-ticket`、`/api/dl` | 否（下载侧另有票据与每日限额，见 §5.4） |
| `/api/mirror-sign`、`/api/icon`、`/api/status` | 否（网页端共用，签名由服务端代持） |
| `/api/ping` | 否（在线心跳，未激活设备也要能上报，见 §3.1） |

### 2.3 官方构建签名

签名是「这个包由官方流水线产出」的凭证，密钥**不在任何仓库里**，只在打包流水线的 Secret 中。

```
signature = hex( HMAC-SHA256( CSH_BUILD_SECRET, "v1|" + buildId ) )
```

| 环节 | 做法 |
|---|---|
| 生成 | 维护者按上述算法对构建号签名 |
| 注入 | 编译期写入程序集元数据：`-p:CshBuildStampB64=<base64("v1|buildId|sig|issuedAt")>` |
| 读取 | 运行时读 `AssemblyMetadata["CshBuildStamp"]` → base64 解码；读不到则视为社区版 |
| 轮换 | 服务端同时接受 `CSH_BUILD_SECRET` 与 `CSH_BUILD_SECRET_OLD`，旧密钥可保留一个发布周期 |

注意事项：

- **不要**把签名写进独立的明文文件随包分发；签名放进程序集只是抬高复制门槛，并不构成安全边界。
- 构建号必须与签名内的一致；改版本号忘了重签，会被判为无效签名（静默降级为「需要激活」，不会报错）。
- 签名有效时，服务端在放行响应里附一个 **30 天**的令牌（`X-CSH-Lic`）。之后即便签名校验因密钥轮换失效，令牌到期前仍可用。

### 2.4 自行编译版与激活码

仓库公开，任何人都能编译出连得上后端的二进制，因此自行编译版不带签名，只能走激活码。

| 项 | 规定 |
|---|---|
| 激活码长度 | 16 字符，字母表 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`（Crockford base32，无 I/L/O/U） |
| 展示格式 | `CSH-XXXX-XXXX-XXXX-XXXX`；服务端会自动剥掉 `CSH` 前缀并忽略分隔符与大小写 |
| 兑换端点 | `POST /api/license/activate`，body `{ code, device, build, version }` |
| 成功响应 | `{ success: true, token, expiresAt }`，令牌默认 **365 天** |
| 失败响应 | HTTP 400 `{ error: "激活码无效。" / "激活码格式不对。" }` |
| 尝试上限 | 同一来源每日 **30 次**（`CSH_LIC_TRY_PER_DAY`），超限 429 |

```bash
curl -sS -X POST https://api.classsoftwarehub.cn/api/license/activate \
  -H 'Content-Type: application/json' \
  -d '{"code":"CSH-4K7M-9Q2X-TZ8B-HJ5N","device":"3b1f9c0d7a2e4f81","build":"1.2.0-local","version":"1.2.0"}'
```

激活码由维护者用离线工具签发（纯 HMAC，不建表、不联网），因此：

- 服务端**无法**单条作废激活码，只能换密钥或维护黑名单 —— 申请时请说明用途与数量；
- 一枚码默认最多绑定 5 台设备（`licCodeMaxDevices`）。绑定记录存在 `lic:cu:<码哈希>`，
  只存设备码哈希，同一台设备重装重复兑换不重复占额度；超出上限返回
  HTTP 409 `{ "code": "csh_code_exhausted", "bound": 5, "limit": 5 }`；
- 兑换记录写入 `lic:d:<device>`（保留 400 天），用于事后核查异常设备。

> 令牌与设备码强绑定。服务端**不再签发设备码为空的令牌**（历史上那类令牌对所有设备通用），
> 因此 `X-CSH-Device` 是必需头，缺失时即使构建签名有效也不会下发 `X-CSH-Lic`。

### 2.5 判定顺序

服务端对受保护路由按下列顺序判定，命中即返回，不再往下走：

| 序 | 条件 | 结果 |
|---|---|---|
| 1 | `X-CSH-Lic` 验签通过、未过期、设备码一致 | 放行 |
| 2 | `X-CSH-Build` + `X-CSH-Sig` 校验通过 | 放行；带设备码时下发 30 天令牌，无设备码只放行本请求 |
| 3 | 完全不带 `X-CSH-Build`，且服务端设置了旧客户端豁免截止日 `CSH_LIC_LEGACY_UNTIL` 且未到期 | 放行（过渡措施，当前未启用） |
| 4 | 浏览器来源：`Sec-Fetch-Mode` + `Sec-Fetch-Site` + `Origin`/`Referer` 白名单 + 正常浏览器 UA | 放行（网页端专用，桌面端不要模仿） |
| 5 | 未开闸（`CSH_LIC_ENFORCE=false` 且未到 `CSH_LIC_ENFORCE_AT`） | 放行，仅在服务端记 `license: would deny` |
| 6 | 其余 | **403** + 下列正文 |

第 4 条只在 `licBrowserStrict` 开启（默认）时生效。关闭后会退回「`Sec-Fetch-Mode` 存在即可」
的旧判定，仅用于线上站点被误伤的应急场景。桌面端**不要**依赖这条链路：它提高的是伪造门槛，
不是安全边界，一旦浏览器侧判定策略调整就会失效。

```json
{
  "error": "您使用的 ClassSoftwareHub 不是正版，请输入激活码激活。",
  "code": "csh_license_required"
}
```

开闸时间点由服务端控制（当前为 `2026-12-02T00:00:00Z` 自动生效）。**客户端不要试图推断是否已开闸**，一律按「收到该 `code` 就引导激活」处理。

### 2.6 客户端必须实现的三件事

1. **每个受保护请求都带头**。不要只在「设置页激活」时带；闸门是逐请求判定的。
2. **捕获响应头里的令牌**。官方包首次请求后就会拿到 `X-CSH-Lic`，存下来，后续请求直接复用，避免每次都走验签。
3. **识别 403 并按需重放**。判据是正文 `code` 以 `csh_license` 开头，而不是状态码本身 —— 403 也可能来自其它业务拒绝。激活成功后重放原请求一次。

参考实现（本仓库，可直接对照）：
`src/Services/License/ClientAuthHandler.cs`（头注入、令牌捕获、403 识别与重放）、
`src/Services/License/LicenseStore.cs`（本地凭证读写）、
`src/Core/BuildIdentity.cs`（元数据读取）。

```csharp
// 头注入（等价于上文的 Authorize 方法）
request.Headers.TryAddWithoutValidation("X-CSH-Build", buildId);
if (signature.Length > 0)
    request.Headers.TryAddWithoutValidation("X-CSH-Sig", signature);
request.Headers.TryAddWithoutValidation("X-CSH-Device", deviceCode);
request.Headers.TryAddWithoutValidation("X-CSH-Ver", version);
if (token.Length > 0)
    request.Headers.TryAddWithoutValidation("X-CSH-Lic", token);
```

### 2.7 设备码

服务端只要求「同一台机器每次启动算出同一个值」，算法由客户端自定，**不要求与其它端一致**。约束：

- 长度 8–64 字符（下载票据另有 8–256 的限制，见 §5.4，建议统一按 16 位十六进制输出）；
- 换硬件后设备码变化属预期行为，用户需重新激活 —— 界面文案应提前讲明；
- 不要把 MAC 地址、磁盘序列号等原始硬件标识直接上送，先做单向哈希。

Win7 移植版的做法可参考：持久化随机 ID（`device-id.txt`）+ 机器名 + 用户名 + CPU 核数 + 系统版本 → SHA-256 取前 16 位。

## 3. 配额限流

所有限额都可在服务端用环境变量覆盖，下表为当前生效值。

| 维度 | 端点 | 默认限额 | 覆盖变量 | 超限响应 |
|---|---|---|---|---|
| 上传签名 · 单 IP | `/api/oss-sign` | 20 次/天 | `SIGN_PER_IP_PER_DAY` | 429，`scope: "ip"` |
| 上传签名 · 全站次数 | `/api/oss-sign` | 3000 次/天 | `SIGN_GLOBAL_PER_DAY` | 429，`scope: "global"` |
| 上传签名 · 全站流量 | `/api/oss-sign` | 20 GiB/天 | `SIGN_GLOBAL_BYTES_PER_DAY` | 429，`scope: "global"` |
| 投稿 · 单设备 | `/api/submit` | 6 次/24 小时 | `SUBMIT_MAX_PER_DAY` | 429，中文文案 |
| 投稿 · 待审条数 | `/api/submit` | 3 条/设备 | `SUBMIT_MAX_PENDING` | 429，中文文案 |
| 下载 · 单设备 | `/api/dl-ticket` | 25 次/天 | `DL_DAILY_LIMIT` | 429，含 `used` / `limit` / `remaining` |
| 下载 · 单 IP（兜底） | `/api/dl-ticket` | 每设备额度 × 8（默认 200） | `DL_IP_DAILY_CAP` | 429，`scope: "ip"` |
| 喊话 · 单配对码 | `/api/announce/send` | 10 秒 1 条 | 固定常量 | 429 `{ error: "rate_limited" }` |
| 激活码尝试 · 单来源 | `/api/license/activate` | 30 次/天 | `CSH_LIC_TRY_PER_DAY` | 429，中文文案 |
| 激活码绑定 · 单码 | `/api/license/activate` | 5 台设备 | `CSH_LIC_CODE_MAX_DEVICES` | 409 `csh_code_exhausted` |

投稿与下载的计数键都由服务端派生，客户端字段只作参数、不作凭证：

- 投稿：客户端若不带 `_设备`（或 `fp`），服务端退回按可信 IP 摘要计数，
  6 次/24 小时与待审 3 条**照常生效**；
- 下载：有设备码按设备码建桶，无设备码按「IP + UA」建桶，另有一本按 IP 的总账兜底
  —— 轮换设备码换不出新额度。

超限响应示例（上传）：

```json
{ "error": "上传请求过于频繁，请稍后再试。", "scope": "ip" }
```

客户端处理原则：

- **不要自动重试 429**。这些配额按天（或 24 小时窗口）计算，重试只会继续累计失败请求。应把服务端文案直接展示给用户，并给出替代路径（改用 GitHub 外链、明天再试）。
- 429 文案是给人看的，可以直接显示；400 的文案同理。不必自己另写一套错误话术。
- 上传前先本地预校验文件大小与类型，避免为了拿一个 413 白白消耗一次签名配额（见 §4.2）。

### 3.1 在线心跳 `/api/ping`

管理后台「在线设备」以这个端点为主口径。它与教室喊话**无关** —— 喊话轮询出厂默认关闭，
若在线统计只认喊话心跳，绝大多数装好的机器在后台永远不出现。

| 项 | 约定 |
|---|---|
| 请求 | `GET /api/ping`（`POST` 同义） |
| 必需头 | `X-CSH-Did`（设备标识），见 §2.7 |
| 响应 | `200 { "ok": true, "ts": 1751..., "identified": 1 }`；缺设备码时仍回 200，但 `identified: 0` 且不计入在线 |
| 建议节奏 | 60 秒一次，进程存活期间持续；进程启动后立刻打一次 |
| 限额 | 每设备 12 次/分钟（`repPingMin`）、2000 次/天（`repPingDay`） |
| 是否过闸门 | 否 —— 未激活设备也要能上报，否则后台看不到「装了但没激活」的那部分机器 |

服务端在**任意**带设备码的 `/api/*` 请求上都会顺带登记一次在线，ping 的作用是让
「用户挂着主界面、不产生业务请求」的机器也保持可见。在线窗口为 300 秒，因此
偶发一两次心跳失败不会掉线。

客户端实现要点：

- 失败静默：不要弹窗、不要写状态行。按 60 → 120 → 240 → 300 秒退避，成功立即恢复常规节奏；
- 按入口顺序依次尝试，任一入口返回 2xx 即算成功；收到 4xx 说明请求被拒（配额或来源判定），换入口没有意义；
- 不要把它接在喊话开关上 —— 两者生命周期不同。

参考实现：本仓库 `src/Services/PresenceService.cs`。

## 4. 内容校验

### 4.1 投稿 `/api/submit`

| 规则 | 说明 |
|---|---|
| 来源必填 | 必须「上传了安装包」（下载项含 `upload/` 开头的 key）或填写 GitHub 仓库；纯外链会被 403 拒绝 |
| 字段白名单 | `id` 小写英文/数字/短横线且以字母数字开头、≤ 60 字符；`name` ≤ 120；`tagline` ≤ 300；`description` ≤ 8000 |
| 分类白名单 | `classroom` / `office` / `system` / `media` / `network` / `utility`，旧分类已废弃 |
| 下载项 | 最多 5 个；地址协议只允许 `http(s)://` 或 `oss://` |
| 平台 | `platforms` 最多 16 个，元素匹配 `^[a-z0-9][a-z0-9.-]{0,30}$`；每平台版本 key 最多 32 个 |
| 文件真实性 | 下载项里引用的 `upload/` 对象必须在服务端登记表中存在，且未被清理；否则 400 并返回 `invalid` 数组，提示用户重新上传 |
| 提交者标识 | `_设备` 或 `fp` 字段取 SHA-256 前 16 位作为提交者 ID，用于每日计数与待审统计 |

### 4.2 上传签名 `/api/oss-sign`

| 规则 | 说明 |
|---|---|
| 大小上限 | 普通上传 2.5 GiB；图标 1 MiB |
| Content-Type 锁定 | 服务端把 `contentType` 签进 URL，PUT 时必须原样携带；不带会被 OSS 回 `SignatureDoesNotMatch` |
| 类型白名单 | 只接受形如 `type/subtype` 的规范值，非法值一律降级为 `application/octet-stream` |
| key 规则 | 由服务端生成（`upload/YYYY/MM/<uniq>-<安全化文件名>`），客户端不得指定 |
| 上传后登记 | 服务端写入登记表；未登记的对象会被 GC 清理，投稿校验也过不了 |

### 4.3 回声洞与反馈

| 端点 | 约束 |
|---|---|
| `/api/echocave` | 正文 ≤ 200 字；内容经 `age` 公钥加密后再上送（服务端不持有私钥） |
| `/api/feedback` | 标题 ≤ 80；详情 ≤ 4000；联系方式 ≤ 4000；`kind` ∈ `report` / `suggestion`；`subkind` ∈ `interaction` / `link` / `other` |

### 4.4 教室喊话 `/api/announce/*`

| 规则 | 说明 |
|---|---|
| 鉴权 | 6 位数字配对码；`send` 与 `list` 凭配对码，`poll` 另需 `deviceId` |
| 文本 | ≤ 100 字；发送者名 ≤ 20 字 |
| 时长 | 10–120 秒，缺省 30 |
| 节流 | 同一配对码 10 秒内只受理 1 条 |
| 有效期 | 消息 180 秒后失效；设备绑定 12 小时无心跳自动解绑 |
| 目标 | `targets` 只能取已绑定的设备 ID，非法值静默丢弃；过滤后为空返回 `no_device` |

## 5. 下载链路

### 5.1 取票

`POST /api/dl-ticket`，body `{ key, fp, prefer? }`。`fp` 为设备指纹（8–256 字符），`key` 只允许 `upload/`、`soft/`、`releases/` 前缀。

响应关键字段：`mode`（`relay` / `backend` / `direct`）、`url`、`expiresIn`、`dailyLimit`、`remaining`。

### 5.2 票据约束

| 项 | 规定 |
|---|---|
| 有效期 | 15 分钟（`direct` 模式按文件大小分档，更短） |
| 绑定 | HMAC 覆盖 `key + 设备指纹哈希 + mode`，任一项不符即 403 |
| 一次性 | 不作废，但过期后必须回站重新取票（410） |
| 转发 | 票据 URL 有效期内可被复制；这是刻意接受的取舍，靠短有效期限制影响面 |

### 5.3 `/api/dl` 的校验

| 情形 | 响应 |
|---|---|
| `key` 前缀非法 | 400 `下载地址无效` |
| `e` 已过期 | 410 `下载链接已过期，请回站点重新点击下载` |
| 签名不匹配 | 403 `下载地址无效` |
| `f`（设备指纹）与票据不符 | 403 `设备校验失败，请回站点重新点击下载` |
| `key` 已从登记表删除 | 404 `文件已被清理` |

### 5.4 每日限额

每设备每天 25 次取票（按 `fp` 哈希分桶计数）。超限返回：

```json
{
  "error": "今天的下载额度已用完（每台设备每天 25 次），明天再来吧",
  "used": 25, "limit": 25, "remaining": 0
}
```

**一个文件的多个分卷应按一次下载计**，客户端不要为同一目标反复取票；重试同一 URL 时票据仍在有效期内，直接复用。

同一条出口 IP 另有更宽的总账（默认每设备额度 × 8）。教室、机房共用 NAT 时整网共享这一份额度，
属于预期行为；命中时返回：

```json
{ "error": "这个网络的今日下载次数已达上限（200 次），明天再来吧", "scope": "ip" }
```

取票接口在 `DL_SIGN_SECRET` 未配置时直接返回 503，不会退化成空密钥签名 —— 客户端把它当
「服务暂不可用」处理即可，不要重试。

### 5.5 加速签名 `/api/mirror-sign`

`GET /api/mirror-sign?url=<GitHub 文件直链>`，只接受：

- `github.com/<owner>/<repo>/releases/download/...` 与 `/archive/...`
- `objects.githubusercontent.com`、`github-releases.githubusercontent.com`、`codeload.github.com`、`raw.githubusercontent.com`

其它地址一律 400 `仅支持 GitHub 文件直链`。节点密钥由服务端持有，客户端不需要也不应该拿到。

## 6. 错误响应约定

所有错误响应为 JSON，正文形如 `{ "error": "<中文说明>", "code"?: "<机器码>", ... }`。`error` 是面向用户的话术，可直接展示；`code` 与附加字段供程序分支使用。

| HTTP | code / 字段 | 语义 | 客户端建议动作 |
|---|---|---|---|
| 403 | `csh_license_required` | 需要激活 | 弹激活引导；成功后重放原请求 |
| 429 | `scope: "ip"` | 本机上传过于频繁 | 明示「稍后再试」，禁用上传按钮倒计时 |
| 429 | `scope: "global"` | 全站上传配额用尽 | 引导改用 GitHub / 官网外链 |
| 429 | 无 `code` | 投稿 / 下载 / 喊话 / 激活码频次超限 | 展示文案，不自动重试 |
| 413 | — | 文件超过体积上限 | 本地预校验，提示换分卷或外链 |
| 400 | — | 字段格式或长度不合规 | 展示 `error`；`invalid` 数组可高亮对应下载项 |
| 403 | — | 投稿缺来源 / 下载票据签名不符 | 回投稿页补来源；回站重新取票 |
| 404 | — | 对象已被清理 | 提示重新上传 |
| 410 | — | 票据过期 | 重新调用 `/api/dl-ticket` 取票后重试 |
| 502 | — | 加速节点签发失败 | 回退 GitHub 官方直链 |
| 503 | — | 该能力未配置（上传 / 下载 / 激活 / 加速） | 提示「服务暂不可用」，不要重试 |

`/api/status` 无需鉴权，会返回 `enforce` / `enforceAt` / `buildSecret` / `licenseSecret` 等布尔与时间字段，便于排查「是我没带签名」还是「服务端没配密钥」；它只暴露配置的有无，不泄露任何密钥值。

## 7. 接入自检清单

按顺序逐项验证，全部通过再接真实用户。

| # | 检查项 | 预期 |
|---|---|---|
| 1 | 不带任何 `X-CSH-*` 头请求 `/api/status` | 200，`ok: true` |
| 2 | 带完整头请求 `/api/echocave` | 200；响应头含 `X-CSH-Lic`（官方包）或 403（社区版，若已开闸） |
| 3 | 把令牌存下后重启客户端，再请求 | 200，且不再出现新的 `X-CSH-Lic` |
| 4 | 故意把 `X-CSH-Sig` 改一位 | 403 `csh_license_required`（观察期则仍 200，服务端日志出现 `license: would deny`） |
| 5 | 用 `X-CSH-Device` 换一个值重放旧令牌 | 403（令牌与设备码绑定） |
| 6 | 提交一条只填外链的投稿 | 403，文案指向「先上传或填 GitHub」 |
| 7 | 上传 2.6 GiB 文件 | 413，且**未**消耗签名配额（本地预校验应先拦下） |
| 8 | 同一设备连取 26 次下载票据 | 第 26 次 429，`remaining: 0` |
| 9 | 把 `/api/dl` 的 `e` 参数改成过去时间 | 410，文案提示回站重取 |

冒烟脚本：后端仓库 `smoke.mjs`（闸门 / 提交 / 计数）、`smoke-blob.mjs`（存储层）。本地 `node smoke.mjs` 可跑通逻辑分支，真实 Blob 行为以线上为准。

## 8. 边界与禁止事项

这些约束是**服务端判定**，不是客户端礼貌。以下行为视为滥用，会被直接拦下或事后追责：

| 禁止 | 原因与后果 |
|---|---|
| 把构建签名硬编码进源码、写进公开 Issue/日志 | 签名等同官方身份；泄露后必须轮换密钥，所有旧包立即失去自动授权 |
| 把 `CSH_BUILD_SECRET` / `CSH_LICENSE_SECRET` 放进客户端或仓库 | 服务端密钥一旦外泄，整套闸门失效；仓库历史视为永久公开 |
| 多个用户共用同一个激活令牌 | 令牌绑定设备码，换机即失效；异常设备会被登记核查 |
| 客户端提示「激活成功」但服务端并未下发令牌 | 服务端才是唯一判定方；伪造成功只会让后续请求继续 403，责任归客户端 |
| 为绕过配额轮换设备码 / IP | 计数按设备与来源分桶，轮换属于规避行为，可直接封来源 |
| 对生产环境做压测、循环重试 429 | 全站配额是共享的，压测会波及其它用户与上传通道 |
| 把 `/api/dl` 票据长期缓存或二次分发 | 票据 15 分钟过期且绑定设备，分发无意义且会触达频次上限 |

反向说明一条：**客户端无法自证清白**。所有判定必须在服务端完成，客户端实现只负责「如实上报身份 + 如实展示结果」。任何试图在客户端做安全边界的方案都不被接受。

## 9. 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| 所有受保护请求 403，`/api/status` 正常 | 未带 `X-CSH-Build`，或签名无效 | 确认构建号与签名一致；社区版走激活码 |
| 官方包偶发 403，重启后恢复 | 令牌被旧值覆盖（多进程并发写） | 令牌写入加锁，读到新值再覆盖 |
| 上传 PUT 回 `SignatureDoesNotMatch` | 未原样携带响应里的 `contentType` | 按响应头设置，不要依赖库的默认值 |
| 投稿 400，`invalid` 里有 `upload/...` | 引用的对象未登记或已被 GC | 重新上传后再提交 |
| 下载 403 `设备校验失败` | `fp` 与取票时不一致 | 设备码算法要跨启动稳定，不要每次随机 |
| 喊话 429 `rate_limited` | 10 秒内重复发送 | 按钮做发送冷却 |
| 429 且 `scope: "global"` | 全站上传配额用尽 | 引导用户走 GitHub / 官网直链，次日恢复 |
| 界面显示已激活但请求仍 403 | 令牌已过期（365 天）或设备码变了 | 重新输入激活码 |
