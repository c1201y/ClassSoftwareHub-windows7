# 教室喊话功能设计

> 状态：设计稿（未实现） · 2026-10-12 · 对应版本线 dv1.1.1-insider1.0
>
> 需求来源：参考市售"教师远程喊话小喇叭"类产品（手机发送 → 教室电脑全屏弹窗 + 语音播报 → 播完自动消失，安静不打扰课堂）。本设计将该能力并入 ClassSoftwareHub，复用既有桌面留言展示层与 submit/cshapi 服务端通道。

## 1. 背景与目标

### 1.1 现状盘点（可直接复用的基建）

| 既有设施 | 位置 | 在本功能中的角色 |
|---|---|---|
| 桌面留言全屏窗 | `Views/MessageFullscreenWindow.axaml(.cs)` | 喊话窗的展示模板（大字、置顶、全屏、Esc 退出全部现成） |
| 桌面留言悬浮窗 | `Views/MessageWindow.axaml(.cs)` | 备选：非全屏的轻量展示形态 |
| submit 中继通道 | `Services/SubmitEndpoint.cs` / `SubmitClient.cs` | 多域名按序回退、记住成功入口，喊话请求走同一套入口策略 |
| 服务端 Worker + DO/KV | `cshapi.132614.xyz` / `submit.132614.xyz` | 新增 `/api/announce/*` 两组接口 |
| 设备指纹 | `DeviceFingerprint` | 轮询请求的 `deviceId` 来源 |
| 链路日志 | `AppLog.Begin/Step/Done/Warn/Fail` | announce 链路打点，排障口径与 update/upload 链路一致 |

### 1.2 目标

1. 老师用手机浏览器（无需安装任何 App）向指定教室机发送一句话，教室机全屏弹窗展示并可语音朗读，播完自动消失。
2. 教室机平时**零存在**：不弹任何东西、不占前台，仅在收到喊话时响应。
3. 防滥用：只有持有配对码的人能对对应教室机喊话。
4. 全链路可观测（AppLog 打点），失败可从 `app.log` 定位。

### 1.3 非目标（第一版不做）

- 多机广播（一对多喊话）。
- 喊话历史存档与回放。
- 图片/附件喊话。

## 2. 总体架构

```
手机/电脑浏览器                    Cloudflare Worker                教室机（桌面端）
┌──────────────┐   POST send    ┌──────────────────┐             ┌──────────────────┐
│ 喊话页        │ ─────────────→ │ 校验配对码+限流    │             │ AnnounceService   │
│ 配对码+内容   │               │ 写入 DO（消费即删）│             │ 每 30s 轮询 poll  │
└──────────────┘               └────────┬─────────┘             │ （携 deviceId+   │
                                        │ DO 存待播报消息        │   配对码，顺带续绑）│
                                        ▼                       └────────┬─────────┘
                               GET poll ←───────────────────────────────┘
                               有消息 200 {id,text,from} → 全屏喊话窗 + 提示音 + TTS → 自动消失
                               无消息 204 → 继续睡
```

通道选型结论：**短轮询（默认 30s，可调）**。理由：

- 喊话非即时聊天，30s 内送达可接受；WebSocket 在 Win7 + 学校代理环境下的断线重连/代理穿透成本高，第一版不引入。
- 短轮询实现最简单（`HttpClient` + 计时器），且与既有 `SubmitEndpoint` 回退策略天然兼容。

## 3. 服务端设计（Worker + DO）

### 3.1 配对码绑定机制

**不设独立 bind 接口**：桌面端在每次 poll 请求里携带 `deviceId` + `pairCode`，Worker 顺带刷新绑定关系（`pairCode → deviceId`，TTL 12h）。效果：

- 教室机只要在正常轮询，绑定就一直有效；停轮询超 12h 绑定自动失效（配对码回收）。
- 换配对码 = 桌面端重新生成后下一次 poll 自动覆盖旧绑定。
- 无需"先注册再使用"的启动顺序依赖。

配对码规格：6 位数字（10^6 空间），桌面端本地随机生成、存 `announce.json`，设置页展示（大字号）。

### 3.2 接口定义

统一约定：仅 HTTPS；请求/响应 UTF-8 JSON；错误统一 `{"error": "<code>"}` + 对应 HTTP 状态码。

#### POST `/api/announce/send`

发送喊话（网页端调用）。

请求：

```json
{
  "pairCode": "384162",
  "text": "请李明同学到办公室",
  "from": "教导处",
  "duration": 30
}
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `pairCode` | string | 是 | 6 位数字 |
| `text` | string | 是 | 1~100 字符，去除首尾空白 |
| `from` | string | 否 | ≤20 字符，展示为"×××说" |
| `duration` | int | 否 | 弹窗停留秒数，10~120，默认 30 |

响应 `200`：

```json
{ "ok": true, "id": "a1b2c3d4" }
```

错误：

| 状态码 | error | 说明 |
|---|---|---|
| 400 | `bad_request` | 字段缺失/超限 |
| 403 | `unknown_pair` | 配对码无效或绑定已过期 |
| 429 | `rate_limited` | 同一配对码 10s 内重复发送 |
| 500 | `internal` | DO 写入失败 |

服务端处理：校验通过后写 DO（key = `announce:<deviceId>`，value 含 `id/text/from/ts/duration`，TTL 90s——超过 90s 未被取走视为教室机离线，消息自动过期，不做离线补投）。

#### GET `/api/announce/poll?deviceId={id}&pairCode={code}`

教室机轮询取件。

响应：

- `204 No Content`：无待播报消息（大多数请求落在这里，Worker 侧不读写 DO 值，仅刷新绑定 TTL）。
- `200`：

```json
{
  "id": "a1b2c3d4",
  "text": "请李明同学到办公室",
  "from": "教导处",
  "duration": 30,
  "ts": 1760260000
}
```

**取走即删**：返回 200 的同时删除 DO 中的待播报条目，防止重复投递与重放。

错误：`400 bad_request`（参数缺失）、`403 unknown_pair`（配对码与 deviceId 不匹配——绑定被顶掉或过期，桌面端收到后提示用户在发送端重新输入新码）。

### 3.3 防滥用与限流

| 措施 | 参数 | 说明 |
|---|---|---|
| 配对码 | 6 位数字 | 10^6 空间，配合限流使枚举不可行 |
| 发送限流 | 1 次 / 10s / 配对码 | DO 计数器实现 |
| 文本长度 | ≤100 字符 | 防滥用长文刷屏 |
| 消息 TTL | 90s | 不做离线补投，避免堆积 |
| CORS | send 接口仅允许站点源 | poll 由桌面端调用，无 CORS 诉求 |
| 内容审计 | 第一版不做 | 列入风险章（8.3） |

### 3.4 请求量估算（免费额度核对）

| 轮询间隔 | 单机日请求 | 30 台日请求 | 对比 Workers 免费额度 10 万/日 |
|---|---|---|---|
| 10s | 8,640 | ≈ 25.9 万 | **超** |
| 30s（默认） | 2,880 | ≈ 8.6 万 | 额度内（占 86%） |
| 60s | 1,440 | ≈ 4.3 万 | 额度内（占 43%） |

结论：默认 30s；设置页提供 15/30/60s 三档，15s 档提示"请求量较大"。若后续机器规模超 30 台或需要更快送达，再评估长轮询（Worker 侧 hold 25s，请求量降为 1/25s）或付费计划。

## 4. 桌面端设计

### 4.1 新增组件

| 组件 | 类型 | 职责 |
|---|---|---|
| `Services/AnnounceService.cs` | 静态类 | 轮询循环、配对码生成与持久化、消费消息后回调 UI |
| `Views/AnnounceWindow.axaml(.cs)` | 窗体 | 全屏喊话展示（模板取自 `MessageFullscreenWindow`），倒计时自动关闭 |
| `Data/AnnounceConfig.cs` | 配置类 | `announce.json` 存档：`Enabled` / `PairCode` / `IntervalSec` / `QuietMode` / `SpeakText` |
| 设置页卡片 | SettingsPage 增区 | 开关、配对码大字展示、间隔档位、安静模式、朗读开关 |

### 4.2 轮询状态机

| 状态 | 含义 | 迁移 |
|---|---|---|
| `Off` | 设置未开启 | 开启且网络可用 → `Idle` |
| `Idle` | 已启用，等待下一轮询点 | 计时到 → `Polling` |
| `Polling` | 请求在途 | 204 → `Idle`；200 → `Announcing`；403 → `Idle`（置"配对失效"标记）；网络失败 → `Idle`（Warn 打点，连续失败静默退避 ×2，上限 120s） |
| `Announcing` | 喊话窗展示中 | 暂停轮询；窗关 → `Idle` |

实现要点：

- 轮询走 `SubmitEndpoint.Ordered()` 同源回退，成功后 `Remember`，与提交流量共享入口健康度。
- 间隔加 ±20% 抖动，避免整点齐发。
- 仅主窗口存活时轮询（单实例退出即停，`ProcessExit` 钩子兜底）。
- AppLog 打点（announce 链路）：轮询起点 `Begin`、204/200/403/异常分别 `Step/Done/Warn/Fail`，与 update 链路口径一致。**日志只记消息 id 与长度，不记内容**（教室机日志可能被学生翻看，隐私优先）。

### 4.3 喊话窗

- 展示：`from`（如有，小字"教导处说"）+ 正文大字（沿用全屏留言的字号缩放逻辑），顶部窄色条标识"远程喊话"与本机区别。
- 关闭：倒计时（`duration`，默认 30s）走完自动关；Esc / 右上角按钮可提前关。
- 声音：弹出时先播提示音（系统 `SystemSounds.Exclamation` 或内置短音），再起 TTS（见 4.4）。
- 展示期间暂停轮询，避免播报未完又弹下一条；窗关闭后下一轮询点自然取走积压消息（DO 里最多一条，天然串行）。

### 4.4 TTS 语音朗读

- 技术：`System.Speech.Synthesis.SpeechSynthesizer`（SAPI5 包装，Win7 自带 SAPI 引擎，.NET 6 下可用；Win7 移植版不引入 .NET 自带的 `Microsoft.VisualBasic` 依赖之外的新运行时）。
- 选声：优先 `GetInstalledVoices()` 里 `zh-CN` 声音（Win7 中文系统通常自带 Microsoft Huihui）；无中文声 → 静默降级为仅提示音 + 弹窗，并在日志 Warn 一条（不弹窗打扰）。
- 安静模式（`QuietMode`）：只弹窗不出声；`SpeakText` 关闭时只提示音不朗读。两者独立开关。
- 朗读期间窗不因倒计时提前关闭而中断——`SpeechSynthesizer.SpeakAsyncCancelAll()` 跟随窗关闭调用，防句柄残留。
- ⚠️ TTS 与窗体同线程可能卡 UI：朗读用 `SpeakAsync`，窗关闭时 `Dispose` 合成器。

## 5. Web 发送端（classsoftwarehub.cn）

- 新增 page「教室喊话」：配对码输入（6 位，数字键盘优化）+ 内容（100 字计数）+ 可选"署名"+ 时长档位（15/30/60s）。
- 发送成功反馈："已送达服务器，教室机最长 30 秒内弹出"。
- 配对码记忆：localStorage 存上次成功码（可清空），方便老师反复使用。
- 页面底部附"教室机如何开启"：路径 = 设置 → 教室喊话 → 开启并读配对码。
- 移动端优先（老师多用手机），单手可达的发送按钮。

## 6. 配置与默认值

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `Enabled` | `false` | 默认关闭，用户主动开启才轮询 |
| `IntervalSec` | `30` | 档位 15/30/60 |
| `QuietMode` | `false` | 安静模式（只弹窗不出声） |
| `SpeakText` | `true` | TTS 朗读开关 |
| `PairCode` | 随机生成 | 首次开启时生成，可手动重置 |

## 7. 里程碑拆分

| 阶段 | 内容 | 验收锚点 |
|---|---|---|
| M1 服务端 | Worker `/api/announce/send|poll` + DO 存取/限流/TTL | curl 手测 204/200/403/429 四态 |
| M2 桌面端核心 | AnnounceService + AnnounceWindow + 配置 + 设置页 | 手机发 → 教室机 30s 内弹窗、自动消失；app.log 链路完整 |
| M3 TTS | 选声/降级/安静模式 | 中文系统朗读正常；无声机器静默降级不报错 |
| M4 Web 发送页 | 喊话页 + 配对码记忆 | 手机浏览器全流程走通 |

## 8. 风险与未决问题

### 8.1 兼容性

| 风险 | 影响 | 对策 |
|---|---|---|
| Win7 无中文 TTS 声音 | 朗读不可用 | 静默降级提示音+弹窗；设置页标注"需系统含中文语音" |
| 学校代理/防火墙拦 poll | 收不到喊话 | 复用 SubmitEndpoint 多域名回退；连续失败退避并 Warn |
| 教室机长期离线 | 消息 90s 过期 | 发送页文案明确"教室机需开机且在线"；不补投 |

### 8.2 服务端额度

- 免费额度按 30 台 × 30s ≈ 8.6 万/日，占免费额度 86%；超过 30 台或调 15s 档需评估长轮询/付费计划（见 3.4）。

### 8.3 安全与内容

- 配对码仅 6 位数字，理论可被枚举：限流 1 次/10s 下穷举完整空间需 ~116 天，风险可控；如需加固可升级 8 位。
- 内容审计缺失：理论上可被持有配对码者发送不当内容。第一版依赖"配对码只给信任的人"；后续可在 Worker 侧接敏感词过滤（列 TODO）。
- 隐私：桌面端日志不记喊话内容（只记 id/长度）；服务端消息消费即删、TTL 90s，不留存。

### 8.4 未决问题（待拍板）

1. 是否需要"全体广播"（一次发全校/多台）？涉及配对码模型扩展（码 → 组），建议二期。
2. 安装版/便携版是否默认同时带该模块？（体积影响可忽略，建议同时带。）
3. 发送端要不要加"常用短语"快捷按钮（"请到办公室""放学后留下"）？成本低，建议 M4 顺带做。
