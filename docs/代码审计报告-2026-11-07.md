### 主审对 P0 的复核说明（重要）

- **已推翻**：底稿里"`C:\Windows.` 尾点 / 尾空格 / `C:\PROGRA~1` 8.3 短名可绕过禁碰名单"这一条 **不成立**。本机 `.NET 6` 实测：
  ```
  Path.GetFullPath("C:\Windows.")      => "C:\Windows"
  Path.GetFullPath("C:\Windows ")      => "C:\Windows"
  Path.GetFullPath("C:\PROGRA~1")      => "C:\Program Files"
  ```
  `IsForbiddenPath` 第一步就是 `Path.GetFullPath`（`LeftoverResolver.cs:948`），三种写法都被归一化成禁区路径，判据会拦住。**不要按这条去改代码**；第 8 条的 TOCTOU 风险仍在，但性质从"字符串绕过"变成"清单来源不可信"。

  ```
  EnumerateFiles(root, "*", AllDirectories) = 1   // 枚举确实跟随 junction
  Directory.Delete(root, true) → IOException      // 递归删除不跟随，且失败
  target\keep.txt 仍在 = True
  ```

|                                                                                                                                                                                                              |        |           |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ | --------- |
| 真实后果是：① `ClearReadOnly`/`File.SetAttributes` 会**改到目录外文件的属性位**；② 树里含自指 junction 时清理必定失败并卡在"清理中"；③ `CopyDir` 跨盘备份会把链接目标复制进隔离区。**不是删穿系统，降为 P2**，修法仍是三处枚举统一 \`EnumerationOptions.AttributesToSkip = ReparsePoint | Hidden | System\`。 |

## 4. 两平台共通的功能性 P1

1. **首页「立即更新」是哑按钮**（`Pages/WelcomePage.axaml.cs:288-303`）：`await UpdateFlow.AskAsync(...)` 的返回值被直接丢弃。用户在弹窗里点「立即更新」或「后台下载」后**什么都不发生**，卡片刷新后仍写"发现新版本"。设置页同一段逻辑（`SettingsPage.axaml.cs:646-659`）是按 `UpdateChoice` 正确分派的，照抄即可。**主审已逐行复核，100% 可复现。**
2. **AppLog ↔ LogHome ABBA 锁序反转**（`Services/LogHome.cs:107-132` + `Core/AppLog.cs:230-232`）：写日志持 `AppLog.Gate` 求 `LogHome.Gate`，首次建会话持 `LogHome.Gate` 回调 `AppLog.Error` 求 `AppLog.Gate` → 启动期可能整进程死锁白屏。**主审已复核锁链成立**，是否已在实机撞到待验证。
3. **OSS PUT 无任何超时/空闲看门狗**（`Services/OssUpload.cs:264-298`）：`HttpClient.Timeout = Infinite`，`ct` 不带 `CancelAfter`。半开连接让进度停在 99% 永不结束；与 `DownloadService` 的 45 秒口径不一致。
4. **后台心跳/代签走授权闸门**（`PresenceService.cs:45`、`MirrorSign.cs:70`、`License/ClientAuthHandler.cs:54`）：60 秒一次的 ping 或下载换签可能直接弹模态「激活正版」，遮住正在进行的下载；且 `MirrorSign.cs:116` 注释写"不带任何认证头"，实现却把 `X-CSH-Lic` 令牌发给 `sign.classsoftwarehub.us.ci`。
5. **官方构建判定可被用户环境变量覆盖**（`Core/BuildIdentity.cs:84-101`、`License/LicenseGate.cs:35`）：`CSH_BUILD_STAMP` 或 exe 同目录文件只要满足"32~128 位十六进制"即让 `IsOfficial=true`，客户端据此跳过激活闸门。服务端是否兜底需另行确认。
6. **激活对话框夹在 HTTP 管道里**（`ClientAuthHandler.cs:54`）：模态框耗时吃满 `HttpClient.Timeout`，激活成功后用已取消的 `ct` 重放必抛 `TaskCanceledException` → "激活成功却报提交失败"。
7. **`EnsureToolPairing` 自己制造孤儿 `tool` 消息**（`Services/HubAi/AiChatService.cs:617-666`）：半应答工具组时先 `rebuilt.Add(tool(X))`，再 `RemoveAt(ownerIndex)`，产出无前置 `tool_calls` 的 tool 消息 → 下一次请求仍 400，会话此后每问必错。防 400 的函数自己造 400。
8. **SSE 干净截断被当成完整回答**（`Services/HubAi/AiClient.cs:183-206`）：EOF 与 `[DONE]` 走同一正常返回路径，不检查 `finish_reason`。CDN 提前礼貌关连接时用户看到半截结论且无任何提示。
9. **会话存档非原子写 + 秒级 id**（`Services/HubAi/ChatSession.cs:370-376`、`:258-263`）：`File.WriteAllText` 写到一半断电 → 半截 JSON 被 `LoadAll` 跳过，整段对话永久消失；同一秒新建两段对话 id 相同互相覆盖。

11. **文档缓存字典跨线程读写**（`Services/Docs/DocLibrary.cs:323`、`:603-618`）：`SyncAsync` 持 `SyncGate`、`EnsureContentAsync` 持 `ContentGate`，却操作同一个 `_cache.Articles` → `InvalidOperationException` 或字典损坏；`PruneCache` 还可能删掉刚写好的缓存文件。
12. **单实例冲突路径在启动线程最多阻塞 ~10.5 秒**（`App.axaml.cs:337-345`、`:446`、`:230-240`）：敲门 3s + 等可见窗口 7.5s + 重抢互斥体 5s，窗口一个像素都没画；并把"托盘常驻 / 向导中"的正常实例判成僵尸后 `p.Kill()` 硬杀（下载、计时、喊话全断）。

## 6. P2 边界 / 泄漏 / 维护性（择要）

- **删除链路**：`AppDataScan.SafeChildren/SafeFiles` 的 try/catch 包不住延迟枚举抛出的 `UnauthorizedAccessException`（`:537-565`）；`PackageRunner.cs:153-171` 重定向 stdout 却从不读，`tar -v` 写满 4KB 管道即死锁；`StartupItems.cs:241-249` 用"最低位"判 `StartupApproved`，`0x06` 口径待真机验证。
