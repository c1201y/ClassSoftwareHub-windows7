# 正版校验（构建签名 + 激活码）

面向维护者的接入说明。目标：仓库公开，但**自建后端只对官方发布版与已授权用户开放**；官方构建全程无感，自行编译版在用到在线服务时提示激活。

---

## 1. 设计原则

| 原则 | 落地方式 |
|---|---|
| 判定必须在服务端 | 客户端只负责**出示凭证**；放行与否由后端（`csh-api` 的 `licenseGuard`）决定。改客户端代码绕不过服务端 |
| 密钥不进仓库 | 构建签名由**打包时**用发布密钥算出，仓库里没有那把钥匙 |
| 官方用户零打扰 | 官方构建首次请求即自动换到短期令牌，之后不再重复验签，界面上没有任何提示 |
| 本地功能不设限 | 只拦在线服务（投稿、反馈、回声洞、喊话、OSS 直传）；工具、系统修复、已有数据一律照旧 |
| 可离线签发 | 激活码是纯 HMAC 结构，签发与校验都不需要数据库 |

## 2. 客户端实现（本仓库已就绪）

| 文件 | 职责 |
|---|---|
| `src/Core/BuildIdentity.cs` | 从程序集元数据（`AssemblyMetadata: CshBuildStamp`，base64）取出构建号与签名；回落环境变量 `CSH_BUILD_STAMP` 与同目录 `build-stamp.txt`；都没有 = 社区版 |
| `src/Core/OfficialApi.cs` | 自建后端专用的 `HttpClient` 工厂，统一挂上授权处理器；同时判定了「哪些域名算自家服务」 |
| `src/Services/License/ClientAuthHandler.cs` | 请求前加凭证头；收到 `csh_license*` 的 401/403 就弹窗、成功后自动重放这次请求 |
| `src/Services/License/LicenseGate.cs` | 保证同一时刻只有一个激活窗；用户放弃后本次运行不再打扰 |
| `src/Services/License/LicenseStore.cs` | 令牌落盘（`%LOCALAPPDATA%\ClassSoftwareHub\license.json`）、设备绑定与过期判定 |
| `src/Services/License/LicenseClient.cs` | 调 `/api/license/activate` 兑换令牌 |
| `src/Services/License/ActivationDialog.cs` | 激活对话框（说明 + 设备码 + 输入框） |
| `src/Pages/SettingsPage.axaml(.cs)` | 「设置 → 授权 → 正版授权」入口，显示三态：官方版 / 已激活 / 未激活 |

已接入的后端调用点：`SubmitClient`（submit / echocave / feedback）、`OssUpload`（oss-sign）、`SubmitPage`（直连 submit）、`AnnounceService`（announce/*）、`MirrorSign`（mirror-sign）。

> 新增任何访问自建后端的 `HttpClient`，都必须从 `OfficialApi.Create(...)` 建，否则拿不到凭证、会被服务端拒绝。

## 3. 请求头契约

客户端在访问自家域名时附带：

| 头 | 内容 | 来源 |
|---|---|---|
| `X-CSH-Build` | 构建号，如 `dv1.2.0-insider1.5+20261102T0730Z` | 签名文件第 2 段 |
| `X-CSH-Sig` | 构建签名（hex，64 字符） | 签名文件第 3 段；社区版不带 |
| `X-CSH-Device` | 设备指纹（16 位 hex） | `DeviceFingerprint.Value` |
| `X-CSH-Ver` | 版本号 | `ShellConfig.ShellVersion` |
| `X-CSH-Lic` | 激活令牌 | 本地 license.json；未激活不带 |

签名算法：`HMAC-SHA256(CSH_BUILD_SECRET, "v1|" + buildId)`，取小写 hex。

## 4. 服务端判定流程

```
请求 → 路由在白名单内？
        ├─ 否 → 原样放行
        └─ 是 → 令牌有效（验签 + 设备匹配 + 未过期）？
                 ├─ 是 → 放行
                 └─ 否 → 构建签名有效？
                          ├─ 是 → 放行，并在响应头下发短期令牌（X-CSH-Lic / X-CSH-Lic-Exp）
                          └─ 否 → 豁免（见下）？
                                   ├─ 浏览器来源 / 旧客户端豁免期内 → 放行
                                   └─ 否 → CSH_LIC_ENFORCE 未开？→ 只记日志放行
                                            └─ 已开 → 403 + {"error":"…不是正版…","code":"csh_license_required"}
```

需要校验的路由：`/api/submit`、`/api/echocave`、`/api/feedback`、`/api/oss-sign`、`/api/announce/*`。

两类豁免：

- **浏览器来源**：网页端（`classsoftwarehub.cn`）也调这些接口，浏览器不可能带构建签名。判据是
  `Origin`/`Referer` 落在 `CSH_LIC_BROWSER_ORIGINS` 白名单内 **且** 请求带 `Sec-Fetch-Mode`
  ——后者是浏览器的禁止修改头，普通 HTTP 客户端不会带。这是提高伪造门槛，不是安全边界。
- **旧客户端**：完全不带 `X-CSH-Build` 的版本在 `CSH_LIC_LEGACY_UNTIL` 之前放行。带了构建号但签名错的不豁免。

**不拦** `/api/mirror-sign`、`/api/dl*`、`/api/icon`、`/api/status`：网页端与下载链路都在用，且下载侧另有票据与限额（见 `Services/MirrorSign.cs` 的说明）。

拒绝响应固定形状（客户端的提交/反馈解析器会直接把它当业务错误显示，正好把这句话给用户看）：

```json
{ "error": "您使用的 ClassSoftwareHub 不是正版，请输入激活码激活。", "code": "csh_license_required" }
```

## 5. 部署（腾讯 EdgeOne Pages）

服务端实现已并入后端仓库 **`c1201y/csh-api`**（本地 `C:\csh-tencent-backend`）的
`functions/api/[[default]].js`，与其他路由同一个文件、同一套 `json()`/KV 助手，无需另建函数：

| 位置 | 内容 |
|---|---|
| `functions/api/[[default]].js` | 常量与算法：`LIC_GATED_PREFIXES`、`licVerifyBuild`、`licVerifyCode`、`licIssueToken`、`licVerifyToken` |
| 同上 `workerFetch` | 入口依次做：CORS 预检 → `/api/license/activate` → `licenseGuard` → `routeRequest`，放行时把 `X-CSH-Lic` 合并进真实响应 |
| 同上 `handleLicenseActivate` | 激活码兑换令牌，含每来源每日尝试上限（`CSH_LIC_TRY_PER_DAY`，默认 30） |
| 同上 `handleStatus` | `/api/status` 的 `license` 字段回报 enforce 开关与密钥是否配好 |

环境变量（EdgeOne 控制台 → 环境变量；敏感值按「密钥」类型填）：

| 变量 | 说明 |
|---|---|
| `CSH_BUILD_SECRET` | 构建签名密钥（必填，与客户端打包用的同一个值） |
| `CSH_BUILD_SECRET_OLD` | 上一把构建密钥，轮换过渡期用；平时留空 |
| `CSH_LICENSE_SECRET` | 激活码与令牌的签名密钥（必填，**不要**与构建密钥相同） |
| `CSH_LIC_ENFORCE` | `true` 才真正拦截；**默认 `false`**＝观察期，只打 `license: would deny` 日志 |
| `CSH_LICENSE_DAYS` | 激活码换来的令牌有效天数，默认 365 |
| `CSH_OFFICIAL_TOKEN_DAYS` | 官方构建自动签发的令牌天数，默认 30 |
| `CSH_LIC_LEGACY_UNTIL` | 旧客户端豁免截止日（ISO 时间）。打开发布前必填，见下 |
| `CSH_LIC_BROWSER_ORIGINS` | 浏览器豁免域名，逗号分隔，默认 `classsoftwarehub.cn,www.classsoftwarehub.cn` |
| `CSH_LIC_TRY_PER_DAY` | 同一来源每天激活尝试上限，默认 30 |

**上线顺序（重要）**：已经装在用户机器上的旧版本没有构建签名，闸门一开就会被拒。

1. 先发布**带签名**的版本（本文这套改动 + 打包注入），让用户先升级；
2. 部署后端，此时 `CSH_LIC_ENFORCE=false` —— 观察 `license: would deny` 日志，确认没有官方客户端被误判；
3. 把 `CSH_LIC_LEGACY_UNTIL` 设成一两个月后、`CSH_LIC_ENFORCE` 改 `true`；
4. 到期后旧版本自然被拦，用户会被提示升级或激活。

> ⚠️ **Win10 桌面端（上游主线）目前没有这套机制**。它发的请求既无构建签名也无会话凭证，
> 完全落进「旧客户端」分支。豁免窗口一到期，Win10 用户会全部被拒。所以要么在到期前把
> `BuildIdentity` + `OfficialApi` 同样移植到 Win10 线，要么把 `CSH_LIC_LEGACY_UNTIL` 往后顺延。
>
> ⚠️ 反向的坑：完全不带 `X-CSH-Build` 的请求在窗口内一律放行，而 fork 出来后**只要删掉这几个头**
> 就落进这一档 —— 所以豁免窗口不能长期开着，也不能留空（留空 = 不豁免，等于立刻拦掉所有旧版）。

验证：`GET /api/status` 的 `license` 字段应显示 `buildSecret`/`licenseSecret` 均为 `true`，
`enforce` 与设置一致；`POST /api/license/activate` 用 `node tools\issue-license-code.mjs 1` 签出的码试激活一次。

> 后端仓库自带的集成测试（Node，模拟 EdgeOne 运行时 + 内存 KV）覆盖了 15 条分支：
> 观察期放行、无凭证拒绝、官方签名发令牌、令牌设备不匹配、错签名、浏览器来源、外站来源、
> 伪造 Origin 无 `Sec-Fetch`、旧客户端豁免期内/外、非保护路由、激活成功、篡改码、短码、非 POST。

## 6. 激活码

16 字符，`CSH-XXXX-XXXX-XXXX-XXXX`；客户端会自动去掉分隔符并转大写。

```
payload 5B = 签发起始日（自 2020-01-01 的天数, uint16 BE） + 序列号（uint24 BE）
mac     5B = HMAC-SHA256(CSH_LICENSE_SECRET, "code|" + payloadHex)[0..5]
码面        = base32(payload + mac)           # 字母表 23456789ABCDEFGHJKLMNPQRSTUVWXYZ
```

校验纯离线：重算 mac 即可，不需要建表。

签发（两种方式，同一算法，产出互认）：

1. **管理后台（推荐）**：打开 `https://<后端域名>/admin` 登录 → 填数量与备注 → 生成。
   除了拿到码，后台还会记录签发与激活情况，并支持封禁设备。
2. **离线脚本（应急，后端不可用时）**：

```powershell
$env:CSH_LICENSE_SECRET = '<密钥>'
node tools\issue-license-code.mjs 5      # 一次签 5 个
```

离线签发的码没有后台记录，用户在客户端激活后会自动以「外部签发」补进后台列表，方便对账。

作废手段分两层：**未激活**的码可在后台吊销（兑换时返回 `403`）；**已激活**的设备只能封禁
（服务端对受保护接口与再次激活都返回 `403 csh_device_banned`），或者轮换 `CSH_LICENSE_SECRET`
让所有已发令牌与旧码一起失效。

令牌（服务端 → 客户端）为 `base64url(payload) + "." + base64url(HMAC[0..16])`，payload：

```json
{ "v": 1, "d": "<设备指纹>", "e": 1790000000, "n": "码尾四位" }
```

`d` 为空表示不绑设备，`e` 为 0 表示长期有效。换机后设备指纹变 → 令牌失效 → 重新激活（界面上写明了这点）。

## 7. 打包：把构建签名编进程序集

签名在 **publish 期**由 csproj 的 `AssemblyMetadata` 写进程序集，发布目录里没有明文文件——
明文 `build-stamp.txt` 谁都能顺手拷走，塞进元数据至少挡住「复制粘贴」这一层。

```powershell
# 1) 生成签名并拿到 base64（密钥取 CSH_BUILD_SECRET 或 .secrets\build-secret.txt）
pwsh tools\make-build-stamp.ps1 -Version 1.2.0-insider1.5
#    末行会直接打印下面两段可直接粘贴的命令

# 2) 发布时把签名编进程序集
$line = (Get-Content dist\build-stamp.txt -Raw).Trim()
$b64  = [Convert]::ToBase64String([System.Text.Encoding]::UTF8.GetBytes($line))
dotnet publish src\ClassSoftwareHub.Win7.csproj -c Release -r win-x64 --self-contained true `
    -p:PublishTrimmed=false -p:PublishReadyToRun=true `
    -p:CshBuildStampB64=$b64 -o dist\win7\app

# 3) 打包（脚本会核对程序集里确实有这份签名）
pwsh tools\pack-win7-portable.ps1 -AppDir dist\win7\app -LauncherDir dist\win7-launcher `
     -Version 1.2.0-insider1.5 -OutRoot dist -Zip -BuildStamp dist\build-stamp.txt
```

不想让明文签名落盘时，直接把 base64 交给打包脚本：

```powershell
pwsh tools\pack-win7-portable.ps1 ... -BuildStampB64 $b64
```

CI（`.github/workflows/win7-release.yml`）走的就是这条路：签名文件写在 `RUNNER_TEMP`，
读完立刻删除，工作区里从头到尾没有 `build-stamp.txt`。

- 打包脚本拿签名去 `ClassSoftwareHub.dll` 里找对应 base64，**找不到就报错**；
  内部自测可加 `-SkipLicenseStamp`。
- 构建号默认 `dv<版本>+<UTC 时间戳>`；CI 里用 commit 短 SHA（`dv<版本>+<sha7>`），同一提交重跑签名一致。
- 签名文件与密钥都在 `.gitignore` 里（`.secrets/`、`build-stamp.txt`），**不要提交**。
- 启动日志会打一行 `构建身份: 官方（…）` 或 `构建身份: 社区（…）`，发版前先确认这一行。
- 程序集里存的是 base64：`strings` 只能看到一串编码，需要先解码；原文不会以明文出现。

## 8. 已知局限

直说，这一层挡的是「clone → 编译 → 直接白嫖」，不是专业破解。

| 手法 | 结果 |
|---|---|
| fork 源码自己编译 | 没有签名 → 403 → 提示激活（**设计目标**） |
| 打包时不带签名直接发 | 同上，但打包脚本会拦 |
| 从官方程序集里把签名抠出来硬编码 | base64 串就在元数据里，反编译/`strings` 能拿到；拿到后能过校验、换 30 天令牌。**这一层只挡复制粘贴，不挡有意破解** |
| 把 `build-stamp.txt` 复制到自建版本目录 | 已失效（新包不再读同目录文件，但旧版客户端仍认） |
| 反编译改客户端跳过弹窗 | 客户端不弹窗，但服务端照样 403，只是没有提示 |
| 用官方二进制重打包分发 | 等效于官方版，无法从请求侧区分（除非加代码签名 + 白名单校验） |

可选的加固（未实现，按需再加）：

1. **设备扇出阈值**：同一构建号下不同设备指纹超过 N 个/天就降级为「必须激活」。用 KV 存 `build:<id>:<device>`（TTL 24h）计数即可。
2. **构建号白名单**：服务端维护已发布构建号列表，签名对但构建号不在表里一律拒绝（让 `build-stamp.txt` 只有配合真实发版才生效）。
3. **令牌缩短有效期**：把 `CSH_OFFICIAL_TOKEN_DAYS` 调到 7，泄露的令牌一周内自然失效。

密钥轮换流程：`csh-api` 后端把现值挪到 `CSH_BUILD_SECRET_OLD`、新的写 `CSH_BUILD_SECRET` → 用新密钥重新打包发版 → 下一个大版本删掉 `_OLD`。期间新旧客户端都能用。

## 9. 验收清单

- [ ] 官方包启动，日志显示 `构建身份: 官方`，全程无激活弹窗，投稿/反馈/喊话正常
- [ ] 用不带 `-p:CshBuildStampB64` 的构建启动，日志显示 `构建身份: 社区`；点投稿 → 弹「不是正版」→ 取消后本次运行不再弹
- [ ] 设置 → 授权 → 正版授权：三态文案正确（官方 / 已激活+到期日 / 未激活）
- [ ] 用签发的激活码激活 → 立即重放原请求成功；重启后仍是已激活
- [ ] 换个 Windows 用户或改机器名 → 设备指纹变化 → 回到未激活（符合预期）
- [ ] 服务端未部署时：客户端提交失败提示「连不上投稿服务」，不应崩溃
