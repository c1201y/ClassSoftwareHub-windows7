# 后端激活与授权逻辑

> 桌面端 / 后端联动说明。基准：后端 `main` 提交 `4c836d0`（2026-11-03 20:28），
> 主文件 `functions/api/[[default]].js` 5799 行 + `functions/admin.js` 1063 行。
> 本文按**代码实际执行顺序**描述，行号可对照源码核对。

---

## 1. 三层身份

后端不认「用户」，只认三种凭证，任意一种成立即放行，优先级从高到低：

| 层 | 凭证 | 谁能拿到 | 有效期 | 用途 |
|---|---|---|---|---|
| ① 设备令牌 | `X-CSH-Lic` | 激活过的设备 / 官方构建自动签发 | 365 天（官方 30 天） | 日常请求的主凭证 |
| ② 构建签名 | `X-CSH-Build` + `X-CSH-Sig` | 只有官方流水线打出的包 | 静态、不随时间失效 | 证明「这个包是官方产出的」 |
| ③ 激活码 | 16 字符本体 | 开发者签发给人 | 一次性兑换成 ① | 自行编译版的正版证明 |

三者共用一把 `CSH_LICENSE_SECRET`（①②的令牌）与一把 `CSH_BUILD_SECRET`（②的签名），密钥只存在于服务端与打包环境。

```
官方包                          自行编译版                    网页端
  │ 内置 build+sig               │ 用户输入激活码               │ 浏览器 Origin
  ▼                              ▼                              ▼
build 验签通过 → 签发 30 天令牌   兑换成功 → 签发 365 天令牌      浏览器豁免（见 §7 W1）
  └──────────────┬───────────────┘                              │
                 ▼                                              │
           X-CSH-Lic 令牌 ───────────────────────────────────────┴─→ 放行
```

## 2. 请求入口的五道关

`workerFetch`（`5497`）是全站唯一入口，顺序固定：

| 序 | 关卡 | 位置 | 行为 |
|---|---|---|---|
| 0 | GC 懒触发 | `onRequest` `5777` | 仅 `POST /api/dl-ticket` 且距上次 > 20 分钟时，`waitUntil` 跑一轮回收 |
| 1 | OPTIONS 预检 | `5506` | 直接回 CORS 头，不鉴权 |
| 2 | **设备信誉闸 `deviceGuard`** | `5516` → `4444` | 见 §2.1；返回 429 = 到此为止 |
| 3 | **激活接口直通** | `5519` | `/api/license/activate` 结束后直接返回，**不过授权闸门**（否则死循环） |
| 4 | 设备触点登记 | `5522` | 带设备码的 `/api/*`（除后台）异步写 `lic:d:<device>`，6 小时节流 |
| 5 | **授权闸 `licenseGuard`** | `5526` → `4705` | 见 §2.2；返回 403 = 到此为止 |

之后才进 `routeRequest`（`5541`）做实际业务，其中 `/api/admin/*` 走独立的后台会话鉴权（Cookie + HMAC），与授权闸门互不影响。

### 2.1 设备信誉闸（先于授权）

只对带合法设备码（`x-csh-did` 或 `x-csh-device`，16–64 位十六进制）的请求生效，否则跳过、交给各接口自己的 IP 配额兜底。

| 步骤 | 存储键 | 结果 |
|---|---|---|
| 封禁检查 | `adm:ban:<device>` | 命中未过期 → 429 `csh_device_banned`，带 `until` |
| 分档限速 | `lic:rep:<device>:<day>` | 按路由档位（每分钟 / 每天）计数，超限 → 429 `csh_device_rate_limited`，带 `scope` / `limit` / `used` |
| 事件日志 | `rep:ev:<device>` | 同类事件 10 分钟一条，供后台回溯 |

注意：**封禁优先于合法性**。被封设备即使令牌仍在有效期内、来兑换激活码，也一律先被挡（`4790`）。

### 2.2 授权闸（后于信誉）

只对下列前缀生效（`4000`）：

```
/api/submit  /api/echocave  /api/feedback  /api/oss-sign  /api/announce/
```

`/api/dl-ticket`、`/api/dl`、`/api/icon`、`/api/mirror-sign`、`/api/status`、`/api/license/activate` **不在其内**（下载侧另有票据与每日限额）。

判定顺序（命中即返回）：

| 序 | 判定 | 位置 | 结果 |
|---|---|---|---|
| 1 | 设备被封 | `4712` | 403 `csh_device_banned` |
| 2 | 令牌验签通过 + 未过期 + 设备码一致 | `4726` | 放行 |
| 3 | 构建签名验签通过 | `4731` | 放行，并在响应头下发新令牌 |
| 4 | 无构建标识 且 旧客户端豁免窗口内 | `4747` | 放行（默认窗口为空 = 不启用） |
| 5 | 浏览器豁免（`Sec-Fetch-Mode` + 白名单 Origin） | `4747` | 放行 |
| 6 | 未开闸 | `4749` | 放行，仅记 `license: would deny` 日志 |
| 7 | 其余 | `4753` | **403** `csh_license_required` |

开闸条件（`4495`）：后台参数优先——若后台显式设过 `licEnforce`，`true` 即开；否则看 `licEnforceAt` 是否已到点。后台未设时回落到环境变量 `CSH_LIC_ENFORCE` / `CSH_LIC_ENFORCE_AT`（默认 `2026-12-02T00:00:00Z` 自动开闸）。

## 3. 密钥与参数

| 名称 | 作用 | 缺省行为 |
|---|---|---|
| `CSH_BUILD_SECRET` | 构建签名 HMAC 密钥 | 缺失 → 任何构建签名都不通过（官方包退化为需激活） |
| `CSH_BUILD_SECRET_OLD` | 上一把构建密钥，轮换过渡 | 空 |
| `CSH_LICENSE_SECRET` | 激活码 MAC + 令牌 HMAC | 缺失 → 令牌校验跳过、构建分支仍放行、`/api/license/activate` 回 503 |
| `CSH_LICENSE_DAYS` | 激活令牌天数 | 365（后台 `licDays` 可覆盖） |
| `CSH_OFFICIAL_TOKEN_DAYS` | 官方构建令牌天数 | 30（后台 `licOfficialDays` 可覆盖） |
| `CSH_LIC_ENFORCE` / `_AT` | 开闸开关 / 开闸时间 | `false` / `2026-12-02T00:00:00Z` |
| `CSH_LIC_LEGACY_UNTIL` | 无构建标识客户端的豁免截止 | 空（不启用） |
| `CSH_LIC_BROWSER_ORIGINS` | 浏览器豁免域名 | `classsoftwarehub.cn,www.classsoftwarehub.cn` |
| `CSH_LIC_TRY_PER_DAY` | 单来源每日激活尝试 | 30 |

后台可在线调（改完立即生效，不必重新部署）：`licEnforce`、`licEnforceAt`、`licLegacyUntil`、`licDays`、`licOfficialDays`、`licTryPerDay`、`licTouchHours`、`licDeviceRegPerIpDay`，以及各类限速档位。

## 4. 激活码

### 4.1 结构

16 个字符，Crockford base32（字母表去掉 `I` `L` `O` `U`，剩 32 个），解码为 **10 字节**：

```
字节 0-1  payload：签发起始日（自 2020-01-01 的天数，uint16 BE）
字节 2-4  payload：序列号（uint24 BE，0–16777215）
字节 5-9  mac：HMAC-SHA256(CSH_LICENSE_SECRET, "code|" + payloadHex)[0..5]
```

校验是**纯离线**的：解 base32 → 重算 MAC → 定长比较。不建表、不查存储（`4610`）。

- 展示形态 `CSH-XXXX-XXXX-XXXX-XXXX` 只是可读格式，服务端 `licNormalizeCode` 会剥掉 `CSH` 前缀、连字符、空格与全角符号（`4599`）。
- 签发：后台 `licMakeCode`（`4212`）或离线工具 `tools/issue-license-code.mjs`，两者算法一致。
- 因为 MAC 只有 40 位，且校验需要密钥，**离线枚举不可行**（攻击者无法本地验证）；在线枚举命中率 1/2^40。

### 4.2 兑换流程（`4765`）

```
POST /api/license/activate
{ code, device, build, version }
```

| 序 | 检查 | 失败响应 |
|---|---|---|
| 1 | 方法 POST | 405 |
| 2 | `CSH_LICENSE_SECRET` 已配置 | 503 |
| 3 | 正文可解析 | 400 |
| 4 | 码长 16（归一化后） | 400 |
| 5 | 设备码非空且形如 16–64 hex | 400 |
| 6 | 设备未被封禁 | 429 `csh_device_banned` |
| 7 | 设备级限速（默认 10 次/分、60 次/天） | 429 `csh_device_rate_limited` |
| 8 | 来源 IP 每日尝试上限 | 429 |
| 9 | 码 MAC 校验 | 400 `激活码无效。` |
| 10 | 码未被后台吊销 | 403 `激活码已被吊销` |
| 11 | 通过 | 200 `{ success, token, expiresAt }` |

成功后会写三处：`lic:d:<device>`（设备档案，400 天）、`rep:ev:`（事件）、后台两份索引（码 → 设备、设备列表）。

**吊销的真实语义**：吊销只拦「下一次兑换」。已经发出去的令牌是离线凭证，服务端无从追回，要让它失效只有两条路——封禁设备，或轮换 `CSH_LICENSE_SECRET`（后者会清空所有授权）。

## 5. 令牌

### 5.1 结构

```
token = base64url(JSON) + "." + base64url(HMAC-SHA256(CSH_LICENSE_SECRET, JSON)[0..16])
JSON  = { v:1, d:"<设备码>", e:<到期 Unix 秒>, n:"<码后四位 或 official>" }
```

- `d` 为空串时，`licVerifyToken` 的 `if (payload.d && payload.d !== device)` 会短路 → 该令牌对**任意设备**有效（见 §7 W3）。
- `e = 0` 表示长期有效。
- 令牌不可伪造（需要密钥），但**不可吊销**，也不含 `jti`。

### 5.2 签发与下发

| 场景 | 天数 | 下发方式 |
|---|---|---|
| 激活码兑换 | `licDays`，默认 365 | 200 响应体的 `token` 字段 |
| 官方构建首次请求 | `licOfficialDays`，默认 30 | 响应头 `X-CSH-Lic` + `X-CSH-Lic-Exp` |

客户端拿到后应立即落盘（`%LOCALAPPDATA%\ClassSoftwareHub\license.json`），后续请求用 `X-CSH-Lic` 带上；官方包的令牌到期前不必再验签。

### 5.3 校验要点

| 检查 | 说明 |
|---|---|
| 结构 | 必须恰好两段，MAC 16 字节 |
| 验签 | 常量时间比较（`licSameBytes`） |
| 版本 | `v` 必须为 1 |
| 设备绑定 | `d` 非空时必须与请求头设备码完全一致 |
| 到期 | `e` 非 0 且已过期 → 失效 |

## 6. 状态机

| 状态 | 判定依据 | 客户端表现 | 出口 |
|---|---|---|---|
| 官方包 | 构建签名有效 | 静默拿到 30 天令牌 | 签名或密钥轮换后转「需激活」 |
| 已激活 | 有效令牌 | 全部在线功能可用 | 到期 / 换机 / 被封 |
| 未激活 | 无令牌、无签名 | 403 `csh_license_required`，弹激活框 | 输入激活码 |
| 令牌过期 | `e` 已过 | 同上 | 重新激活或换官方包 |
| 换硬件 | 设备码变化 | 同上（令牌 `d` 不匹配） | 用新设备码重新激活 |
| 已被封禁 | `adm:ban:<device>` | 429 `csh_device_banned` + 解封时间 | 联系开发者 |
| 码被吊销 | 后台标记 `r` | 403 `激活码已被吊销` | 换新码 |

补一条容易误判的：**开闸前（观察期）所有拒绝都只写日志**，客户端看不出差别。所以「本地测试一切正常」不代表授权链路通了，验收必须看服务端日志里的 `license: would deny` 或直接查令牌是否下发。

## 7. 设计边界与已知弱点

下列条目均已对照当前代码核实，按可利用性排序。前 4 条直接影响「闸门是否成立」。

> **2026-11-04 修复状态**：W1（四件套判定 + `licBrowserStrict`）、W3（不再签发空设备码令牌，
> 校验端要求 `d` 非空且等值）、W4（`licCodeMaxDevices`，默认 5 台）、W5（`sid` 缺失回落 IP 摘要）、
> W6（增加按 IP 的兜底额度）、W8（缺密钥直接 503）已改；W7 与 W9 未动。
> 下文保留修复前的代码与行号，作为问题成因的记录；现行实现以
> `docs/后端审计-2026-11-04.md` §5 的修复记录为准。

### W1 浏览器豁免可被任意客户端伪造（P0，影响面最大）

`4675` 只检查两个请求头：

```js
if (!request.headers.get('sec-fetch-mode')) return false
// 然后比对 Origin/Referer 的 hostname 是否落在白名单
```

`Sec-Fetch-Mode` 对浏览器脚本是禁止修改头，但对 `curl` / 任何 HTTP 客户端只是一个普通 header。因此非官方客户端发送 `Origin: https://classsoftwarehub.cn` + `Sec-Fetch-Mode: cors` 即可命中豁免，开闸后依然零成本通过。**网页端确实需要这条豁免**，但它不能仅凭两个可伪造头判定。

### W2 旧客户端豁免 = 对「不上报构建号」的客户端全开放（P1）

`4694`：只要设置了 `CSH_LIC_LEGACY_UNTIL` 且未到期，**完全不带 `X-CSH-Build`** 的请求直接放行。默认值为空（未启用），但一旦为了兼容老版本打开，任何人不带这个头就绕过了整个闸门。若确需启用，应叠加版本号白名单。

### W3 官方构建可换出「通用令牌」（P1）

`4736` 用请求头里的设备码签发令牌，而该头可以为空 → 令牌 `d:""`，校验时短路为任意设备可用。且构建签名是静态字符串，可从任意官方安装包里提取。合起来：**提取一次签名 → 30 天通用令牌，可全网分发**。修复只需在签发前要求 `deviceIdOk(device)`。

### W4 激活码无消费语义（P1，取决于产品预期）

`4249` 的 `licRecordActivation` 只做 `n += 1` 记账，从不拒绝重复使用；同一码可在任意多台设备上换出 365 天令牌。若「一码一台设备」是商业预期，需在兑换时校验 `hit.u` 是否已被别的设备占用。

### W5 投稿配额可由客户端单方面关闭（P0，与授权无关但同属防滥用）

`1205`：`submitGate` 在拿不到提交者 ID 时 `return { ok: true }`，而 ID 来自客户端提交的 `_设备` / `fp`，长度不符即返回空串（`1138`）。删掉该字段就同时跳过「6 次/24h」与「待审 3 条」两项限制。

### W6 下载每日配额键仍由客户端决定（P0）

`2400` 的注释写着「配额键必须由服务端派生」，但实现是 `const fp = device || ip|ua`，其中 `device` 取自请求头。换个设备码或改 User-Agent 就是新桶，25 次/天形同虚设。真正服务端派生应只用连接 IP（不可自报）。

### W7 配额计数是「读-改-写」，无 CAS（P1）

`submit-tick`（`3578`）、`sign-check`、`repCheck`、`bytes-add` 全部把整张表读出来、改一个数、整表写回。Blob 只提供整体覆盖，并发请求会互相抵消，N 个并发最多 +1。既能被并发放大额度，也会让 `file-put` 丢登记记录（已上传的对象被判「未登记」）。

### W8 `DL_SIGN_SECRET` 缺失时票据可离线伪造（P1，需确认线上已配置）

`2029` 用 `String(env.DL_SIGN_SECRET || '')` 做 HMAC 密钥，`handleDlTicket` 不校验该变量是否存在。密钥为空时算法与拼接格式全在开源代码里，任何人都能自算 `k/e/h/s` 直接调 `/api/dl` 取流，绕过票据、配额与登记校验。

### W9 令牌与签名都没有时间维度

构建签名是 `HMAC(secret, "v1|" + buildId)`，永不过期；令牌不可吊销。这两点是刻意的（否则离线客户端无法验证），代价是「一旦泄露只能换密钥」。`CSH_BUILD_SECRET_OLD` 的存在进一步延长了旧签名的有效期。
