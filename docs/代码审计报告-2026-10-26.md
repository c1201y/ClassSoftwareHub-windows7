## 一、P0（6 项）

### 1. 残留清理可能把整个用户目录当成“残留”并默认勾选删除

证据链：

- `InstallLocation` 原样读入：[InstalledApps.cs:404](../src/Services/InstalledApps.cs#L404)
- 成为 `profile.Location`：[LeftoverResolver.cs:958](../src/Services/LeftoverResolver.cs#L958)
- **只要待清路径在安装目录内就直接判 Strong 并默认勾选**：[LeftoverResolver.cs:292](../src/Services/LeftoverResolver.cs#L292)、[581](../src/Services/LeftoverResolver.cs#L581)
- 禁碰名单只挡 `Desktop/Documents/...` 和叶子名 `Users`，**不挡 `C:\Users\<用户名>` 本身**：[624](../src/Services/LeftoverResolver.cs#L624)、[804](../src/Services/LeftoverResolver.cs#L804)
- 提权清理递归强删：[LeftoverCleaner.cs:763](../src/Services/LeftoverCleaner.cs#L763)

**后果**：坏安装包或手工改过的卸载登记把 `InstallLocation` 写成 `C:\Users\张三`，该目录下所有痕迹都成“强证据默认勾选”，用户点一次清理即递归删除整个 profile。

**修复方向**：校验 `Location` 是合法安装根，禁止等于用户目录/盘根/系统目录；把 profile 根加入禁碰名单；Strong 级别还应校验目录内存在该软件的可执行文件或卸载器。

### 2. 备份失败后直接强删，隔离区承诺失效

位置：[LeftoverCleaner.cs:220](../src/Services/LeftoverCleaner.cs#L220)-237、[268](../src/Services/LeftoverCleaner.cs#L268)、[234](../src/Services/LeftoverCleaner.cs#L234)。

`TryMove` 失败返回 `Failed` 后无条件走 `ForceDelete`；跨盘复制中途失败时，已复制的半份留在隔离区、源目录被整棵删除。用户以为“有备份可恢复”，实际不可恢复。

### 3. `√x` 型函数的零点给出错误“精确结论”

位置：[FunctionClosedForm.cs:582](../src/Services/FunctionClosedForm.cs#L582)、[618](../src/Services/FunctionClosedForm.cs#L618)-622。

`SqrtForm` 调用的 `ZeroOfPower` 是给 `x²=t` 用的，返回 `x = ±√t`。输入 `√x - 2` 得到的是 `x = ±√2`，正确答案是 `x = 4`，且 `√x` 只有一解。错误答案以“精确结论”卡片呈现，会直接被学生抄进作业。

### 4. 数值求根系统性漏掉偶数重根，还能刷出 64 个假根

位置：[EquationSolver.cs:369](../src/Services/EquationSolver.cs#L369)-373。

只认“`|y| < 1e-12`”和“变号”：

- `(x-1.23456)^2 = 0` 在 ±10 区间、步长 0.0005 时，离根最近的采样点 `y≈3.6e-9`，既不满足阈值也不变号 → 判无解。双重根、四重根全部丢失。
- `sin(x) * 1e-15 = 0` 每个采样点都 `<1e-12` → 立刻填满根列表。

绝对阈值同时造成漏解与假解。

### 5. 抽号滚动期间清空名单 → 索引越界 / 把已删名字写进结果

位置：[PickNumberToolPage.axaml.cs:527](../src/Pages/Tools/PickNumberToolPage.axaml.cs#L527)-528、[1080](../src/Pages/Tools/PickNumberToolPage.axaml.cs#L1080)-1088。

滚动期约 1 秒（16×65ms）直接对共享 `_roster` 做 `RollRandom.Next(total)` + 索引；清空按钮没有任何滚动态保护。DEBUG 下全局异常处理 `e.Handled=false`，直接结束进程；Release 下连续抛异常，并可能把已清空的名字写进结果区与去重记录。

### 6. 单实例接管的两条静默失败路径

- 抢回互斥体循环 [App.axaml.cs:195](../src/App.axaml.cs#L195)-205 共 5 秒，**失败后没有任何分支处理**，`_instanceMutex=null` 照常启动 → 可能同时跑两个实例，Inno Setup 的 `AppMutex` 判据也失效，升级时可能覆盖正在运行的程序文件。
- 探测线程把“`SiblingPids` 返回空表”当成“对方已退出” → [App.axaml.cs:328](../src/App.axaml.cs#L328)；而权限不足时 `SiblingPids` 正是静默返回空表 → [WindowProbe.cs:116](../src/Platform/WindowProbe.cs#L116)-119。首个实例初始化中用户再双击一次，第二实例会 `Environment.Exit(0)` 且无提示。

## 四、屎山 / 技术债（结构性）

### 1. 规模与耦合

- `src/Views/ToolSidebarWindow.axaml.cs` 171 KB / 3583 行
- `src/MainWindow.axaml.cs` 2296 行
- `src/Pages/SidebarLayoutPage.axaml.cs` 2153 行
- `SettingsPage` / `HubAiPage` / `ShellPage` 均 1200+ 行

托盘、下载弹窗、可见性看门狗、WebView 宿主全挤在一个类里，状态字段跨 `async void` 共享——上面多数竞态都源于此。

### 2. 异步与异常治理缺失

- **70 个 `async void`**，分布在 32 个文件
- **293 个空 `catch`**，分布在 65 个文件
- **1064 个 catch 对 415 个日志点**
- 发布版把 UI 异常一律标记 `Handled`，等于把可诊断失败变成静默坏死

### 3. P/Invoke 散乱

**202 个 `DllImport` 分布在 34 个文件**。`NativeMethods` 拆分后仍有 `WindowChrome.cs` 私有重复声明（[WindowChrome.cs:272](../src/Core/WindowChrome.cs#L272)），同一个 DWM 常量出现 1 和 2 两个版本。

### 4. 同一功能两套实现

- 普通下载走 `DownloadService` 的并行分片，更新包走 `UpdateService` 的单流增量哈希，各自维护 Referer/超时/进度语义；`X-Api-Key` 正是在这条缝里漏掉的。
- 时钟设置的 `CopyInto/CopyOf` 与 `CopyFrom/Clone` 完全重复（[ClockToolPage.axaml.cs:600](../src/Pages/Tools/ClockToolPage.axaml.cs#L600)），归档注释明确说“别在调用方再手抄一遍”，代码照抄。

### 5. 静态可变状态

`UpdateService._badRouteUntil`、`DownloadGates`、`MirrorSign.Cache`、`RoundedCorners.Applied/Logged`、`SettingsStore.Current` 都是进程级可变状态，缺少并发策略或清理策略。

### 6. 死代码

- `FunctionPlotPage.Num`（[470](../src/Pages/FunctionPlotPage.axaml.cs#L470)）无人调用
- `ClockSettings.Acrylic` 两支 try/catch 完全相同（[149](../src/Core/ClockSettings.cs#L149)-161）
- `UpdateService` 的“未提供校验值”分支不可达（[244](../src/Services/Updating/UpdateService.cs#L244)-245）

### 7. Win7 承诺与实现错位

“亚克力/云母”只是半透明纯色；`Cascadia Mono`、`Segoe UI Variable Display`、`Bahnschrift` 在干净 Win7 上不存在，选中后静默回退但标签仍写原字体。

### 8. 工程化空白

没有 `Directory.Build.props`、`.editorconfig`、Roslyn 分析器；`tools/package-tests` 只验证解包，**数学/化学/更新/清理/设置没有任何自动化测试**。这是“精确结论给错答案”能长期存活的根因。

### 9. 缓存/导航语义靠注释口口相传

`NavigationCacheMode` 注释与实际 `Frame.CacheSize=2` 不一致，各页对“缓存/重新加载”的描述彼此矛盾。
